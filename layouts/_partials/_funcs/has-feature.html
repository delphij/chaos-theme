This replaced a page-scoped flag that the render hooks set (Store.Set "hasMath" / "hasMermaid") and the gates read. The flag answered the wrong question. Rendering a page's .Summary renders its whole content and then truncates, so the hook fired for a diagram far below the summary divider and set the flag; a list page reading it concluded that the summary it was about to print contained a diagram. On this site that put a 2.5 MB Mermaid library on seven pages to serve the one that actually has a figure, and KaTeX's stylesheet on 89 pages to serve 58. Asking about the markup instead answers exactly the question the gate means. The two places a page can emit a feature's markup are its own .Content and the .Summary of each page it lists, which is what the layouts render -- page.html and page-header.html print .Content, home.html and list.html print both. Known limit: the listing half walks the stored paginator, which is what home.html and list.html print. A section named in site.Params .unpaginatedSections has no stored paginator; list.html then lists _funcs/get-list-pages.html instead, and a feature appearing only there goes undetected.
