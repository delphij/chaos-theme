    space instead: narrower and more even than a typed word space (measured at
    16px, 2px per boundary against 5.33px). The two never stack - once a real

    nothing - so leaving them in would simply give the wider, less typographic

    right thing to emit for any conforming renderer, feed readers included.

    The space is removed only where autospace will put a gap back. It acts
    between an ideograph and a letter or digit, never a symbol, so a space
    before inline code that opens with - / . $ or ~ (--bare, /usr/local,
    .txt) is the only gap that code gets: it has no background, and without
    the space it reads as part of the word before it. See the boundary rules
    below for where that is decided.

    outside

    text-autospace gap, overflow handling drops the entire CJK text node back

    splitting off the final break unit bounds that fallback without breaking
    kinsoku or punctuation kerning.

All of these stay string rewrites over rendered HTML because none is a Markdown
construct: Goldmark has no hook for them, and Hugo cannot load a custom
Goldmark extension. (Everything that IS a Markdown construct - math, images,
links, diagrams - is handled structurally instead, by the per-output-format
render hooks in layouts/_markup/. Line-wrap newlines are handled at parse time
by markup.goldmark.extensions.cjk, which is why they never reach code blocks.)
The ruby patterns are bounded and newline-free so one stray bracket cannot let
a match run away.
