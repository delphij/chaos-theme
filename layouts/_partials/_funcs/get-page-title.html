{{- /* Returns the display title for a page. Hugo derives a list page's title from the section or taxonomy name ("tags", "categories", "posts") and does not localize it, so those are looked up in the i18n table -- lowercased, so the lookup does not depend on capitalizeListTitles. Term and regular pages are never translated. A title the author wrote in front matter is returned untouched. Probing the i18n table with it was wrong twice over: a translation could override what the author asked for, and any list page whose title is not an i18n key logged WARN i18n|MISSING_TRANSLATION|zh-CN|归档 on every build -- content/archives/_index.md sets title: "归档", which is a title, not a key. That warning is why the build could not be run under --panicOnWarning. The derived names are probed only when the theme ships a translation for them. Any other section ("pages", "notes") or taxonomy a site defines has no key, and probing it logged the same warning; its derived title is kept as Hugo made it. @context {page} page The page to resolve the title for. @returns {string} The localized display title. @example: {{ partial "_funcs/get-page-title.html" . }} */}} {{- $title := .Title -}} {{- $translated := slice "posts" "archives" "categories" "tags" "series" -}} {{- if and (in (slice "section" "taxonomy") .Kind) (not .Params.title) (in $translated (lower $title)) -}} {{- with T (lower $title) -}} {{- $title = . -}} {{- end -}} {{- end -}} {{- return $title -}}
