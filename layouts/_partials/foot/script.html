{{- /* Emits one script tag: built through js.Build, minified and fingerprinted with an integrity hash in production, unminified with an external source map in development. Every script the theme loads goes through here, so the build options and the tag's attributes cannot drift apart between one script and the next -- which is what happened when the Mermaid glue was written inline in a template and so never saw js.Build at all. target fixes the syntax floor of the output. Without it the emitted syntax is whatever the source happens to be, so the baseline would be decided by accident. The theme targets Baseline Widely Available (see Browser Support in README.md); in 2026 that admits all syntax through es2024, the regexp v flag being its newest. Newer syntax may still be written: esbuild lowers it, rather than silently raising what browsers the theme requires. Not esnext, which would let ES2025 syntax (import attributes, regexp modifiers) through to Safari 17. It cannot express the real floor, which is set by runtime APIs rather than syntax; esbuild polyfills none of those, so they are held to the same Baseline rule by review, not by the build. @param {string} . The asset path, e.g. "js/main.js". @example: {{ partial "foot/script.html" "js/main.js" }} */ -}} {{- $opts := dict "minify" (not hugo.IsDevelopment) "sourceMap" (cond hugo.IsDevelopment "external" "") "target" "es2024" "targetPath" . -}} {{- with resources.Get . -}} {{- with . | js.Build $opts -}} {{- if hugo.IsDevelopment -}} {{- else -}} {{- with . | fingerprint -}} {{- end -}} {{- end -}} {{- end -}} {{- end -}}
